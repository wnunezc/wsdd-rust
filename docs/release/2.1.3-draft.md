# WSDD 2.1.3

WSDD 2.1.3 is a patch release candidate for manual validation after `2.1.2`.

The current local MSI is for manual testing. The intentional PHP 5.6 log-test failure
was removed after user validation; the normal PHP 5.6 image builds successfully.

## Projects And Logs

- Fixes removing the last project volume leaving a null root-level volumes key.
  The section is omitted when empty and recreated by the existing Add Project
  branch when required. Named-volume and service-mount sections remain distinct.
- Validates Compose before PHP runtime replacement, removes the previous manual
  stop/rm sequence, and tracks attempted recreation before up can fail so the
  existing best-effort rollback can attempt runtime restoration.
- Adds multi-project selection and confirmed removal, plus confirmed PHP container
  removal with cleanup of its associated projects. External Docker deletions do not
  trigger automatic project removal.
- Adds ascending/descending sorting by Name, Domain and numeric PHP version, and
  a case-insensitive partial/exact filter over those three columns.
- Limits selection to visible projects when filtering.
- Uses a single project toolbar with an integrated filter clear button and
  right-aligned removal action. Name/Domain expand across the table width;
  selection, PHP and Toolbox keep compact fixed widths. Sortable headers show
  direction indicators and hover feedback, aligned left with their data. Rows use
  a compact 24 logical pixel height and 6 pixel vertical spacing.
- Drains process log bridges before reporting results or rollback, scopes progress
  keys to each command, and reports a concise failure instead of replaying the
  captured transcript in red. Full process output remains in the daily deploy file.
- Checks Docker volume removal exit status and reloads project inventory after
  batch completion, including partial failures.

## Runtime Rebuild / PHP Admin

- Base startup recovers existing
  containers by exact name, independent of their Compose project labels, and
  creates only missing services with --no-recreate --no-deps. This prevents
  recovery from recreating MySQL/phpMyAdmin and colliding with a legacy-owned
  proxy name. Six focused tests and clippy passed; included in this test MSI.
- Adds Deploy PHP in the toolbar between CMD Terminal and Add Project, with a
  version selector and Deploy dialog. Missing Webmin credentials are requested;
  no project registration or project volume is created. Existing containers are
  not replaced. The selected service is built before up; running state and Apache
  HTTP readiness are checked, without certifying PHP-Admin readiness.
- The seven PHP Dockerfiles now install the official fixed
  PHP-Admin 1.0.0 ZIP in a build-time RUN after Webmin configuration, verifying
  SHA256 before extraction. Existing CMD bytes and Dev/Release priority are unchanged.
  The local test MSI below includes these Dockerfiles and the Deploy PHP button.
  All 85 source resource files match the embedded ZIP by SHA256. No Docker image
  build or real container deployment was performed for this packaging task.
  Release HTTP readiness remains blocked by missing direct Apache probe routing
  and WSDD_PHP_ADMIN_APACHE_PROBE_HOST. See the maintenance integration report.

- Keeps the installed-environment reconciliation introduced in `2.1.2`.
- Ensures Deploy rebuilds the PHP runtime image with `docker compose up --build --force-recreate`
  after WSDD synchronizes managed PHP Dockerfiles and compose files.
- Fixes the case where local Dockerfiles were updated but an existing PHP container kept running
  from an older image without new extensions such as `mysqli`.
- Preserves project volumes and project entries while rebuilding the shared PHP runtime container.
- Adds the first local integration package for WSDD-PHP-Admin on PHP 8.3, exposed as
  `phpadmin83.wsdd.dock` through the PHP 8.3 runtime on internal port `8989`.
- Provisions persistent state/log mounts for `/var/lib/wsdd-php-admin` and
  `/var/log/wsdd-php-admin` without bundling the PHP-Admin application.
- The PHP 8.3 container now selects exactly one WSDD-PHP-Admin root at startup:
  `/var/www/html/phpadmin.dock` for development when its CLI is executable, otherwise
  `/opt/wsdd-php-admin` for release packaging. WSDD delegates startup to
  `runtime:start` and no longer starts the PHP-Admin agent and web server separately.
- WSDD does not bundle or extract a WSDD-PHP-Admin artifact. If no CLI exists at the selected
  runtime paths, the container logs that PHP-Admin is unavailable and continues with Apache/Webmin.
- Windows hosts synchronization now uses the same internal PHP endpoint list as mkcert, so
  `phpadmin83.wsdd.dock` is added to the WSDD-managed hosts block together with the PHP 8.3
  internal service domains.
- WSDD-PHP-Admin runtime support is normalized across PHP 5.6, 7.2, 7.4, 8.1, 8.2, 8.3, and
  8.4. Each PHP runtime has a versioned admin endpoint (`phpadminXX.wsdd.dock`), version-scoped
  state/log mounts, port `8989`, and a `runtime:start` handoff when its dev project CLI is mounted.
- PHP 8.3 keeps the existing dev project root `/var/www/html/phpadmin.dock`; the other versions use
  `/var/www/html/phpadminXX.dock` for compatibility testing.

## Validation

- `cargo fmt --all -- --check`
- `cargo check --workspace`
- `cargo clippy --workspace -- -D warnings`
- `$env:WSDD_SKIP_WINDOWS_MANIFEST='1'; cargo test --workspace`
- `cargo wix-msi --nocapture`

Current test build validation: install the MSI, check project sorting/filtering and
compact layout, then Deploy a PHP 5.6 project normally. The earlier intentional failure
test confirmed that the final red error no longer replays the full transcript.
Before the latest Remove fix, automated checks passed: 166 unit, 10 release validation and 6 launcher tests,
including a real failing stdout/stderr process and log bridge regression tests.
The Remove fix passed check, fmt, clippy and 21 targeted YAML/lifecycle tests;
the full test suite was not rerun to avoid unrelated installed-log writes.
