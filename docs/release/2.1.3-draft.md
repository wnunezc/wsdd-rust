# WSDD 2.1.3

This release includes the changes developed since the public 2.1.0 release.

## PHP Runtimes And WSDD-PHP-Admin

- Adds **Deploy PHP** beside CMD Terminal: choose a PHP version and deploy its
  container without registering a project. Existing containers are not replaced.
- Normalizes WSDD-PHP-Admin infrastructure across PHP 5.6, 7.2, 7.4, 8.1, 8.2,
  8.3 and 8.4, with dedicated `phpadminXX.wsdd.dock` URLs, internal port 8989,
  version-scoped persistent state/logs, hosts entries and certificates.
- Docker image builds download the official PHP-Admin 1.0.0 package and verify
  its SHA256 before installation. The application is not embedded in the MSI or
  resource ZIP. Building PHP images requires access to the package source.
- Startup selects one root and delegates to `runtime:start`: executable mounted
  development CLI first, otherwise `/opt/wsdd-php-admin`. PHP 8.3 uses the development
  project `phpadmin.dock`; other versions use `phpadminXX.dock`.
- Adds a separate managed Apache probe vhost using the same root selection, without
  changing public proxy routing or overwriting project vhost blocks.
- Synchronizes managed resources before PHP runtime rebuilds while preserving
  project entries and mounts. Fixes legacy PHP 5.6 package/Webmin build failures.
- Applies the updated MySQL memory configuration and container resource limits.

## Projects And Logs

- Adds confirmed multi-project removal and PHP-container removal with associated
  project cleanup. Deleting containers outside WSDD does not delete project records.
- Adds ascending/descending Name, Domain and numeric PHP sorting, plus a
  case-insensitive filter across those columns and selection of visible rows.
- Refines the project toolbar, column alignment and compact row layout.
- Prevents full command output from being replayed in red after a failure; drains
  streamed output before final status and retains full output in the deploy log.
- Checks volume-removal exit status and refreshes project inventory after partial
  batch failures. Batch removal stops at the first failure; it is not atomic.

## Recovery And Compose

- Fixes an empty root-level `volumes:` section after removing the last project.
  A subsequent project addition recreates the mapping as needed.
- Validates Compose before replacing a PHP runtime and improves best-effort rollback
  tracking when recreation fails.
- Recovers existing base containers by exact name, including legacy Compose ownership,
  and creates only missing services without recreating unrelated containers.

## Validation And Limits

- Automated formatting, compile, lint and workspace tests run in GitHub Actions.
  The release workflow builds the MSI and publishes its SHA256 checksum.
- Source resources and the embedded Docker-Structure ZIP were checked for matching
  content across all 92 files.
- Manual PHP 8.4 Release verification confirmed agent/web using the same installed
  root, successful reconciliation/readiness, loopback port 8989, authenticated
  Apache probe and runtime-health responses, and rejection of unauthenticated probes.
- Development mode, other PHP versions, extension operations, and external browser/TLS
  acceptance are not certified by that PHP 8.4 check. PHP 8.0 and 8.5 are not included.
- Operational log readability and credential redaction remain tracked in
  [issue #15](https://github.com/wnunezc/wsdd-rust/issues/15). Review and redact
  technical build logs before sharing them.

## Updating

Install the MSI, then rebuild the PHP containers whose images need the updated
Dockerfiles. Updating WSDD alone does not replace already-running PHP images.
Back up the environment before updating. Persistent project and PHP-Admin data
remain mounted; rebuilding is not a request to delete those data directories.
