# WSDD 2.2.0

Changes since the published 2.1.3 release.

## Container organization and deployment

- Groups managed containers in Docker Desktop as `wsdd-core` (proxy, MySQL and phpMyAdmin), `wsdd-web` (PHP runtimes) and `wsdd-tools` (optional services). Container names, network, ports and mounts retain their existing contract.
- Checks Compose ownership before operations on fixed-name containers. WSDD reports an incompatible legacy owner instead of adopting or removing that container.
- Shows measured stages for PHP, project and optional-service deployment. During PHP image builds, the UI shows the latest observed BuildKit step without inventing a percentage or ETA.
- Writes a redacted log for each deployment operation. The UI can expand live output and open or copy the complete operation log; the existing daily log remains available.

## Settings and tools

- Reduces Settings to the language selector. WSL storage and recovery settings move to a separate Tools dialog. Existing saved configuration and secrets remain available to their current runtime flows.
- Adds dedicated Tools dialogs for ngrok, Redis, Memcached and Mailpit. Save stores options without deploying; Deploy applies the selected service; Stop stops its container without deleting its volume. ngrok can also check its Agent API.
- Shows deployment stages and open/copy log actions in the Tools dialogs. Redis, Memcached and Mailpit have not yet been validated end to end against a live Docker installation.

## Diagnostics

- Masks recognized WSDD credentials in application and PowerShell diagnostics, deployment logs and copied output. Command execution and saved credentials are not changed; Docker's own logs and older files are not rewritten.
- Corrects username masking so a standalone username is hidden without altering a hostname such as `phpadmin56.wsdd.dock`.

## Updating

The installer carries the updated Compose and PowerShell resources. WSDD synchronizes managed templates while preserving project options and data directories. If an existing fixed-name container still has an incompatible Compose project label, WSDD reports it for explicit user-directed migration rather than changing that container automatically.
